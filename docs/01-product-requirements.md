# To-Do List 产品需求与业务规则

## 产品定位

面向需要管理日常工作与生活任务的个人用户，提供启动后即可使用的离线桌面工具。首版以 Windows 为验收平台，保留 Electron 跨平台结构；macOS 和 Linux 安装包在各自环境验证后另行交付。

用户应能够快速记录任务、查看未完成事项、补充说明并确认完成，关闭应用后继续使用原有数据。企业级要求体现在模块职责、数据一致性、失败恢复、可访问性和可维护文档。

## 功能范围

### 核心功能

- **FR-01 新增任务**：填写必填标题和可选描述，创建成功后进入未完成状态。
- **FR-02 编辑任务**：修改标题、描述并明确保存；取消操作保留原始内容。
- **FR-03 删除任务**：删除后从正常列表移除，提供 8 秒撤销入口。
- **FR-04 切换状态**：通过复选框设为已完成或未完成。
- **FR-05 任务列表**：显示标题、可用描述摘要、完成状态和创建时间，支持查看完整内容。
- **FR-06 状态筛选**：全部任务、未完成、已完成三种筛选。
- **FR-07 持久化**：每次成功操作即时写入 SQLite，正常关闭与重启后结果一致。
- **FR-08 交互反馈**：提供输入校验、提交中、成功、失败、空列表和读取异常状态。

8 秒撤销是本项目的交互选择，不是用户需求规定的时间。它使单条删除保持快捷，同时降低误操作的成本。

### 增强功能

- **FR-09 搜索**：在标题和描述中进行关键词包含匹配。
- **FR-10 自动排序**：最新创建、最早创建、优先级从高到低。
- **FR-11 优先级**：高、普通、低，默认普通。
- **FR-12 手动排序**：拖拽调整任务全局顺序，同时提供上移和下移操作。

首版范围包含以上增强能力，按核心任务闭环、组合查询、优先级和手动排序的顺序组织开发与验收。实际执行结果单独记录，不以功能范围替代通过结论。

### 桌面体验补充需求

- **FR-13 自定义窗口**：使用本项目图标及自定义顶部栏，初始 1200 × 800，按屏幕工作区适配并保存后续尺寸；文本输入聚焦使用单层边框。
- **FR-14 自定义选择器**：排序、优先级与密度使用统一组件，支持鼠标和键盘，不使用原生 select 外观。
- **FR-15 侧栏折叠**：开关位于侧栏底部信息区上方，展开显示名称与数量，折叠显示图标与提示，选择持久化。
- **FR-16 专注小窗**：默认右下角 360 × 480，可拖动和切换置顶，显示未完成任务并与主窗口实时同步。两个窗口独立，关闭或最小化任一窗口不关闭另一个。
- **FR-17 安装交付**：仅提供 Windows x64 NSIS 安装程序，用户可以选择磁盘中的安装目录。
- **FR-18 优先级旗帜**：高为暖红、普通为深绿、低为灰色，结合文字在列表、表单、选项和小窗保持一致。
- **FR-19 系统托盘**：Windows 通知区域图标的右键菜单提供打开工作台、打开小窗、新建任务、置顶或关闭小窗、立即备份、退出应用。工作台关闭后直接隐藏，保留草稿且不弹出丢弃确认；只有明确退出意图才终止应用并关闭两个窗口。快捷操作不注册为任务栏 JumpList。
- **FR-20 正式版引导任务**：打包后的正式应用仅在全新任务数据库首次初始化时写入两条引导任务，一条已完成、一条未完成，均可正常编辑和删除。已有用户、升级或删除全部任务后不补入；开发环境及仓储测试默认空库。

### 后续扩展边界

截止日期、标签、提醒和多清单可沿模块边界增加。本轮不实现账号、云同步、协作、附件、日历视图、番茄钟或自然语言日期解析；这些能力需要独立的产品规则与验收范围。

## 任务字段与约束

- **稳定标识**：由主进程生成 UUID，所有操作按 ID 定位；允许多个任务标题相同。
- **标题**：纯文本，必填，提交前去除首尾空白，1 至 120 个 Unicode 码点。前后端使用同一校验规则，不按 UTF-16 长度分别计数。
- **描述**：纯文本，可为空，最多 2,000 个 Unicode 码点；保留用户换行，统一换行为 LF。界面不将任务内容作为 HTML 执行。
- **完成状态**：仅未完成、已完成两种，新增默认未完成。
- **优先级**：低为 0、普通为 1、高为 2，默认普通。
- **手动顺序**：独立于创建时间，自动排序不会覆盖它。
- **创建时间**：主进程生成，创建后不可编辑。
- **更新时间**：内容、状态、删除或恢复成功时更新；仅重排不改变内容更新时间。
- **完成时间**：设为已完成时记录；恢复未完成时清空。
- **修订号**：每次写入递增，用于识别旧编辑覆盖和过期重排。

时间以 UTC 毫秒存储，按操作系统地区和时区展示。主进程负责生成业务时间，渲染层不决定持久化时间。拒绝 NUL 等不可见控制字符；描述允许换行和制表符。

标题与描述上限是本项目约定，可在评审时调整。字符计数与输入法组合输入必须使用统一测试样例。

## 核心用户流程

### 新增

1. 点击顶部“新增任务”或使用 Ctrl+N，打开新增面板并聚焦标题。
2. 输入标题，可填写描述并选择优先级。
3. 点击“创建任务”或按 Ctrl+Enter 提交。输入法组合输入期间不触发快捷提交。
4. 提交中保留表单并防止重复创建。数据库提交成功后更新列表和计数，关闭新增面板，提示“任务已创建”。
5. 如果当前筛选或搜索使新任务不可见，提示“任务已创建，当前条件下不可见”，并提供“查看任务”。该动作在处理当前草稿后切换为全部任务、清空搜索并选中该任务，保留原排序。

新增不默默改变用户的筛选。手动排序下新任务追加到全局末尾；最新创建排序下显示在最前。首次使用默认全部任务和最新创建。

### 编辑

1. 点击任务标题区域或任务菜单中的“编辑”，打开同一详情面板。
2. 输入内容只修改本地草稿，列表继续呈现已提交的数据。
3. 保存时提交允许修改的字段及初始修订号，数据库提交后同步最新任务。
4. 保存失败时保留草稿、焦点和错误提示，允许重试。

编辑表单不进行隐藏的自动保存，避免关闭面板与保存时机不清晰。无实际修改时保存按钮不可用。

### 完成与恢复未完成

点击复选框后，任务进入提交中状态。成功后同步复选框、完成样式和全局计数。未完成筛选中完成的任务退出列表；已完成筛选中恢复的任务同理。反馈说明实际变化。

完成切换不修改创建时间、优先级或手动顺序。全部任务视图不强制将已完成任务沉底，以维持所选排序的可预测性。

同一任务的复选框、编辑和删除操作串行处理。若该任务存在未保存草稿，先执行“保存并继续、放弃修改、取消”的草稿保护流程，再执行状态变更。

### 删除与撤销

单条删除采用“立即提交删除加限时撤销”，不再叠加日常确认弹窗。操作菜单中明确显示“删除任务”，避免与完成按钮相邻误触。

删除提交成功后显示任务标题、撤销按钮和剩余时间。8 秒从主进程提交时开始计算，不因刷新、悬停、聚焦或重启延长。撤销实际恢复原任务 ID、内容、完成状态、创建时间及顺序字段，并更新更新时间。

撤销通知可由键盘聚焦；用户可通过通知中的按钮执行撤销。恢复成功后是否显示任务仍由当前筛选和搜索决定；不可见时提供“查看任务”。撤销失败不得伪造恢复结果。

连续删除生成独立撤销记录。通知区最多展开最近 3 条，其他有效记录可在通知区展开查看；每条独立计时。重启后只恢复仍在原期限内的撤销入口，过期记录不延长。到期删除项由主进程空闲时或下次启动清理，本版不提供回收站。

如果撤销期间全局顺序已经调整，恢复任务按照保留的顺序值插入；值相同时用 ID 稳定比较，不移动其他任务。下一次成功手动重排再统一编号。

## 搜索与筛选

处理顺序为：排除已删除任务，应用状态筛选，应用关键词过滤，应用排序，最后展示。

搜索只针对标题和描述。检索副本进行 NFKC 归一化、首尾去空白和英文小写转换；原始内容保持不变。单次输入作为完整关键词包含匹配，不增加分词、正则或模糊匹配。关键词最多 200 个 Unicode 码点，输入停顿 150 毫秒后更新；输入法组合完成后再过滤。

左侧状态计数依据所有正常任务计算，不随搜索改变。结果区单独显示当前匹配数量。清空搜索只移除关键词，不重置状态筛选和排序。

筛选或搜索变化不销毁已打开的编辑草稿。详情区域显示“当前任务不在筛选结果中”，允许继续编辑或关闭。

## 排序规则

- **最新创建**：创建时间降序，再按 ID 升序。
- **最早创建**：创建时间升序，再按 ID 升序。
- **优先级**：高、普通、低；同级按创建时间降序，再按 ID 升序。
- **手动排序**：按顺序值升序，再按 ID 升序。

切换排序模式不改写任务数据。排序偏好可以保存；搜索关键词和打开的草稿不跨重启恢复，避免启动后误以为任务缺失。

只有“全部任务、搜索为空、手动排序、没有未保存草稿、没有正在提交的操作”同时满足时启用拖拽及上移下移。其他状态不接受重排，并说明需要切换条件或先保存、取消编辑。

拖动过程中仅展示预览；放下后将完整正常任务 ID 顺序一次性提交。成功后确认顺序；失败恢复原顺序。排序期间集合变化导致版本冲突时，重新读取并提示用户重试。

## 草稿与退出

草稿存在未保存修改时，关闭面板、切换任务、新增另一任务、删除当前任务或退出整个应用均提供三个明确动作：保存并继续、放弃修改、取消。默认焦点为取消；保存失败则停留原位置。工作台的窗口关闭按钮只隐藏到托盘，继续保留当前草稿，不触发丢弃确认。

搜索和筛选不销毁草稿，因此不触发额外确认。对当前正在编辑任务执行内容外的写操作时，同样先解决草稿，避免互相覆盖。

所有已提交操作逐次保存。关闭工作台时隐藏到系统托盘并保留草稿、小窗和任务存储；关闭小窗不改变工作台。托盘“退出应用”处理草稿后，停止接收新写入、等待任务与备份队列，最终关闭所有窗口。强制结束不保证未提交草稿，不能依赖退出事件补存任务。

## 异常与空状态

- 无任务集合：“还没有任务，从记录第一件事开始。”提供新增入口；适用于删除全部引导任务后的正式数据或开发空库。全新正式数据库按 FR-20 显示两条引导记录。
- 筛选无任务：按筛选显示“暂无未完成任务”或“暂无已完成任务”。
- 搜索无结果：显示当前关键词，并提供清除搜索。
- 读取中：显示简洁加载占位，读取完成前不展示空列表结论。
- 初次读取失败：显示重试与可用备份恢复入口，禁止以空数据覆盖原数据库。
- 保存失败：表单就近显示错误，已有任务和输入保留。
- 提交结果未知：提示“正在确认保存结果”，重新读取后再决定是否重试，禁止重复创建。
- 版本冲突：保留草稿并提示重新加载最新内容；重新加载前明确告知将替换当前草稿。

## 成功标准

全部核心需求通过对应验收场景；增强能力启用后，组合筛选、排序、拖拽和重启留存也通过验证。界面中的成功提示必须对应已完成的数据库提交，任何读取或写入失败都不得静默清空用户数据。
